Procure-X architecture

One HTML file runs inside the claude.ai artifact sandbox. Claude reads quotes and writes drafts, plain JavaScript calculates every number, and the buyer approves every step. There are no servers.

01Runtime architecture

Everything the buyer sees is rendered in their own browser from a single state object. The app crosses the sandbox boundary for only three things: Claude (reading and writing), saved views (private storage), and CSV downloads.

02Quote to award: who does what

Each step belongs to one actor. Claude only reads and writes; code validates and calculates; the buyer approves before anything moves on.

Claude draftsFills the create page, extracts rates, answers questions and writes letters, always as structured JSON or reviewable text.
Code calculatesTotals, L1/L2/L3 ranks, 60/20/20 scores, split-award savings, currency conversion and approval rules.
The buyer decidesApproves flagged prices, records approvals, executes the award and sends every notice.

04How it was built

05From prototype to production

  • Browser storage per viewerA shared database with RFx, quotes and audit history, so a buying team works on the same events.
  • Buyer-entered exchange rateThe official daily reference rate, fetched automatically.
  • Notices logged, not sentAn email service and e-signature for award letters.
  • Quotes uploaded by the buyerA supplier portal where vendors upload quotes themselves.
  • Simulated approvalsSingle sign-on with roles, so the CPO and Finance approve in their own queue.
  • Award ends in the appAn ERP connector (SAP or Coupa) that raises the purchase order.
